## designer 2026-10-29
- instruction-gap: the spec binds rest-keyed joints, and every translation and scale key, to "exactly" their rest transform. Blender 5.2's glTF exporter can't meet that. With the fox's export settings (`export_force_sampling`, `export_optimize_animation_size=False`), its keys come out 1-2 float32 steps off the joint nodes' own TRS: translation 1.3e-7, scale 4.2e-7, rotation 6e-8. I measured this with `docs/tasks/desert-arms-walk/scripts/key_diffs.py`. So the build now exports the glb without animations, byte-identical to before, and appends the clips itself (`add_clips` in build_arms.py). Still and translation/scale keys copy the node values. Turned joints use node rotation x pose quaternion, which `scripts/key_convention.py` confirmed is the exporter's own composition (max 1.8e-7). The actions are still built on the rig for a live session. A future spec that wants exact rest keys should know the exporter won't give them. Alternatively, the shared art style could say exact means "as float32 from the same source".
- instruction-gap: the spec gives the walk's wrist trail ("up to 6 degrees") but no sprint value. I used 6 degrees in `Arms_Sprint` too, and recorded it in assets.md.
- instruction-gap: "the hand trails it at the wrist" names no axis. The hand pitches about the elbow's hinge (in the arm's plane), a quarter cycle behind the swing. Measured about the test poses' axes, that is twist 0, flex 1.74 and sideways 4.79 degrees.
- doc-gap: my first amplitude check compared the motion against the same `CLIPS` numbers that drive it, so a wrong number in `CLIPS` could never fail it. A negative test (walk bob set to 2 cm) passed when it should have failed. The checks now use a separate `CLIP_TARGETS` table. A designer note could say that a check's targets must not be the constants that build the thing it checks, and to prove each new check with one negative run.
- tool: glb reading (`read_glb`, `read_accessor`, the clip read-back and the rest-pose vertex/IBM/node comparison) is written into desert/tools/blender/build_arms.py. tools/blender/ has no shared glb reader. build_fox.py and build_hooded_hero.py check their clips without one, and desert-arms-detail's `scripts/compare_joints.py` had its own. That makes it the third hand-written glb accessor reader.
- tool: docs/tasks/desert-arms-walk/scripts/reimport_glb.py re-imports a glb into an empty scene and lists its skinned meshes, armatures and actions. The designer instructions ask for this on every export, and nothing shared does it.

## game-developer cycle 1
- instruction-gap: the project notes say the shell is zsh and to pass multi-word arguments through arrays, but my first loop over `"--sprint --capture x.png"` strings used `$a` unquoted, which zsh doesn't split, so all four bad-argument runs "failed" for the wrong reason (one argument). I caught it from the odd message and re-ran with `arr=(${=a})`. A check list written as strings in the spec invites this; a note that `${=var}` is needed in zsh next to Verification command lists would help.
- tool: scripts/arm_rows.py: given a capture and the same capture rendered without the arms, prints the arms' top row, pixel count and row/column box per half. The no-arms render needs a temporary edit of `arms.pose` in main.cpp (restored afterwards), because the game has no flag to hide the arms. tools/ has nothing for "where is the view model in this capture"; the two arms tasks have both needed it (desert-arms-detail checked the 35% line the same way, by hand).
- doc-gap: none otherwise. `SkinnedModel::blend` allowing `out` to alias an input is documented in skinned.hpp:76, which is what the binding `pose()` relies on.
